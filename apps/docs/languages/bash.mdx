The Shell extractor (tree-sitter-bash) maps CST nodes to canonical concepts for `sh`, `bash`, and `zsh`. Function names come from the `name` field on the function's word; variable assignments and commands label the same way, so no fallback rules are needed.

## Detected concepts

| tree-sitter node type | Canonical concept |
|---|---|
| `function_definition` | Function |
| `command` | CallExpression |
| `command_name` | identifier |
| `variable_assignment` | Variable |
| `simple_expansion` | Variable |
| `declaration_command` | Variable |
| `if_statement` | IfBlock |
| `for_statement` | ForLoop |
| `while_statement` | WhileLoop |
| `case_statement` | SwitchBlock |
| `string` | string_literal |
| `number` | number_literal |

## Example

Renaming a function:

```bash old.sh
total() { echo hi; }
```

```bash new.sh
sum() { echo hi; }
```

Running `differens old.sh new.sh`:

```text
  ~ renamed function `total` to `sum`
  ~ changed function `sum` (`total` → `sum`)
```

## Example: change the body

Keep the declaration name and change what it does:

<CodeGroup>

```bash body-before.sh
total() { echo ready; }
```

```bash body-after.sh
total() { echo done; }
```

</CodeGroup>

```bash
differens body-before.sh body-after.sh
```

```text
  ~ changed function `total` (`ready` → `done`)
```

The report groups the value edit under its containing declaration. Use
`--format=json` to inspect the underlying action and context, or `--format=llm`
for a compact report with source locations.

## Known limitations

- Shell support uses the Bash grammar. Zsh-specific syntax may retain error nodes or produce a partial structural comparison.

- Heredoc bodies are strings; edits inside them report as value changes.
- Command substitutions and pipelines are structure: a pipeline reordering reports as a reorder of call expressions.
