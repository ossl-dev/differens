The Scala extractor maps tree-sitter Scala CST nodes to canonical concepts. Class, object, and definition names come from the standard `name` field; `val` and `var` names come from the pattern field.

## Detected concepts

| tree-sitter node type | Canonical concept |
|---|---|
| `class_definition` | Class |
| `trait_definition` | Trait |
| `object_definition` | SingletonObject |
| `function_definition` | Function |
| `val_definition` | Constant |
| `var_definition` | Variable |
| `package_clause` | Namespace |
| `import_declaration` | Import |
| `if_expression` | IfBlock |
| `match_expression` | MatchBlock |
| `string` | string_literal |
| `boolean_literal` | boolean_literal |

## Example

Renaming a method:

```scala old.scala
class Counter { def total(n: Int): Int = n + 1 }
```

```scala new.scala
class Counter { def sum(n: Int): Int = n + 1 }
```

Running `differens old.scala new.scala`:

```text
  ~ renamed function `total` to `sum` in class `Counter`
```

## Example: change the body

Keep the declaration name and change what it does:

<CodeGroup>

```scala body-before.scala
class Counter { def total(n: Int): Int = n + 1 }
```

```scala body-after.scala
class Counter { def total(n: Int): Int = n + 2 }
```

</CodeGroup>

```bash
differens body-before.scala body-after.scala
```

```text
  ~ changed function `total` (`1` → `2`)
```

The report groups the value edit under its containing declaration. Use
`--format=json` to inspect the underlying action and context, or `--format=llm`
for a compact report with source locations.

## Known limitations

- Implicits and given clauses are structure: adding one reports as an insert on the declaration.
- `var` definitions in some template contexts produce an ERROR node in the grammar; they parse cleanly in class and object bodies.
